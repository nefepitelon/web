# STM hunt 交付与运行说明

入口：`/stm-hunt`。主导航位于「套利对冲Ops」之后。沿用现有 Next.js 应用、账户、Max/管理员权限、数据库及 Vercel 项目，不创建第二套账户或资金托管系统。

## 交付范围与版本

| 交付层 | 已实现内容 |
| --- | --- |
| v1.0 研究终端 | 参考视频的深色密集终端、候选列表、行情与证据、六类 Web3SmartMoney 榜单、TopTrader 与 Alpha Radar、数据质量、关注与地址分组 |
| v1.1 策略与复盘 | S1–S5、参数版本、不可变采集快照、站内提醒、模拟开平仓与费用、按时间推进的历史回放、JSON/CSV 导出 |
| v1.2 受控交易 | Binance USDT 合约审批/确认/执行/保护单/平仓/对账/熔断、BSC PancakeSwap V2 浏览器钱包报价/精确授权/签署/回执结算、采集器 HMAC 接口与链上成交核验 |

这些层合并交付于同一版本，不代表每种链、交易所或上游私有权限均已具备。界面以实时能力状态为准。没有预设收益、虚构持仓、演示成交或人为补入的就绪信号。

## 策略定义

| 策略 | 触发证据与边界 |
| --- | --- |
| S1 趋势共振 | 两小时内 Alpha 候选、已收盘 15 分钟线突破此前 20 根高点、小时量比、至少三个合格交易实体的精确开多/加多。平空和榜单快照不计买入 |
| S2 持续吸筹 | 固定原始实体群体的三个不同源时间、完整持仓数量连续增加。私密/截断仓位剔除；现货还需两个区间内的实际 Swap 证据 |
| S3 链上先锋 | 十分钟内三个独立审核资金集群的确认买入、仍持有、合约风险通过、流动性及可退出路由。仅转账不计成交 |
| S4 分歧撤退 | 原始群体连续减仓且价格上涨，输出退出风险提醒，不自动开空 |
| S5 拥挤过滤 | 同币历史资金费率达到 95 分位、OI 合约数量增加且价格上涨；过滤新仓。风险证据未知时也不放行 |

默认三个实体、量比 1.5、链上流动性 10 万美元；参数可保存新版本。参数是研究假设，不是收益承诺。CEX 实盘在审批及最终提交锁内均重验当前就绪做多信号，并要求 S5 启用且证据正常，不能通过旧 Alpha 执行接口绕过。

## 数据与来源语义

- Web3SmartMoney 读取公开 FOMO、HyperLiquid、Pump、Binance、Lighter、OKX JSON 榜单与公开仓位。来源可能陈旧、缺少时区、截断或私密；不会把更新时间改成采集时间，也不把未知仓位当零仓。
- TopTrader 的排行与共振接口提供研究背景。精确成交接口需要 `STM_TOPTRADER_TOKEN`；未授权时显示受限，不把排行变更推断为开仓。
- Alpha 使用本站扫描器及真实 Binance 行情。市场证据只使用闭合、连续 K 线，OI 使用数量，资金费率使用同币历史分位。未接入真实强平事件。
- 服务器采集每五分钟一次，使用跨实例租约避免重复抓取；保存 30 天紧凑快照。历史回放只能覆盖实际采集后的时间，不能补造上线前历史，也不使用触发后的信息倒推入场。
- BSC 定时扫描只覆盖最多十个全局审核钱包，每次最多 1,000 个确认区块、八笔候选回执，并记录游标与积压；首次启用从最近 1,000 块开始。普通转账只是待核验候选，必须匹配真实注册池与钱包的直接代币转账。公开 RPC 不支持日志或限流时明确降级，游标不会跨过尚未核验的交易；这不是全链无遗漏扫描服务。
- 钱包分组是用户私有状态；全局合格钱包和资金集群审核需要管理员及二次验证。跨平台同一人的身份无法仅凭榜单完全证明。

## 可执行市场

| 市场 | 当前能力 | 必要条件 / 限制 |
| --- | --- | --- |
| Binance USDT 合约 | 模拟及受控实盘 | 已配置交易凭据、管理员二次验证、独立实盘解锁、账户日亏损与风险额度正常、就绪信号、用户确认 |
| CEX 现货 | 模拟 | 新实盘仓位暂停：尚缺完整历史成本与划转核验，不能用零亏损替代未知账户风险 |
| BSC Pancake V2 | 浏览器钱包实盘 | 本站验证并绑定的钱包、USDT/USDC 付款、零税代币、GoPlus 与真实池/流动性检查通过、有效报价、足够 Gas、用户钱包逐笔确认 |
| Solana、其他 EVM 链、其他 DEX | 数据研究与风险展示 | 未实现实盘签署，不显示可交易假状态 |

BSC 报价最长 60 秒、滑点 0.1%–1%、付款和路由合约固定；授权精确额度，再次模拟并估算 Gas 后由钱包签署。提交只登记广播哈希；三次链上确认、发起人/路由/calldata/金额及实际 Transfer 全部匹配才计成交。同一请求和哈希可安全重试，内容不匹配转人工对账并阻止新报价。

BSC 止盈止损是观察价格与人工退出参考，不是链上自动条件单。日亏损仅覆盖 STM 已核验交易的 FIFO 稳定币结果，不含 Gas，也不代表外部钱包完整损益；未知成本会阻止新买入。未托管私钥、未授权自动签名。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/stm-hunt` | 公共研究数据；只有合法会话返回本人私人状态 |
| `POST /api/stm-hunt` | 刷新、关注、策略版本、模拟开平仓、历史回放、提醒已读 |
| `GET/POST /api/stm-hunt/wallets` | 本人地址分组与管理员钱包审核 |
| `GET /api/stm-hunt/export?format=csv` | 私有 CSV；JSON 使用 `format=json`，公式文本已转义 |
| `GET /api/stm-hunt/risk?chain=bsc&address=...` | 合约安全、池与路由证据 |
| `GET/POST /api/stm-hunt/trade` | 本人账户能力、审批、钱包报价、执行与结算 |
| `POST /api/stm-hunt/ingest` | 外部采集器提供 BSC 哈希/钱包/代币，服务器独立核验回执 |
| `GET /api/stm-hunt/cron` | `CRON_SECRET` 授权的采集与站内提醒，不发送外部消息或交易 |

写接口校验同源、用户权限及输入；实盘另校验管理员、二次验证、独立解锁、账户风控和熔断。数据库 `stm_hunt_records` 已启用 RLS，并撤销公共、anon/authenticated 角色直接访问，服务端按用户命名空间隔离。

采集器请求体示例：`{"chain":"bsc","hash":"0x完整交易哈希","wallet":"0x完整钱包地址","token":"0x完整合约地址"}`。使用 `x-stm-timestamp`（秒或毫秒）和 `x-stm-signature`；签名为 HMAC-SHA256(`timestamp + "." + 原始请求体`, `STM_INGEST_SECRET`)。允许时差五分钟、请求 16KB、全局每分钟 120 次，同一事件幂等。没有配置至少 32 字符随机密钥时接口拒绝接收。

## 配置、发布与验收

现有生产数据库、身份验证与交易凭据继续沿用。可选服务端变量：`BSC_RPC_URL`、`STM_TOPTRADER_TOKEN`、`GOPLUS_ACCESS_TOKEN`、`STM_INGEST_SECRET`；已有 `CRON_SECRET` 用于定时采集。禁止使用 `NEXT_PUBLIC_` 保存这些凭据。

构建沿用 `npm run build -- --webpack`，打包当前本地全部平台、生成 Prisma Client，并在 Vercel 生产构建应用迁移。新增迁移：`20261119180000_add_stm_hunt`。先创建 production staged 部署并验证，再 promote 到现有域名。不要把 `.env*`、日志、账户状态或私钥上传为源码。

验收：类型检查与全站测试；真实来源返回和缺失降级；生产表 RLS 与临时记录读写清理；未登录的私人写入、未签名采集及未授权 cron 应拒绝；部署产物与入口检查。实盘交易仅在用户实际配置资金账户后由用户主动确认，部署验收不使用真实资金试单。
