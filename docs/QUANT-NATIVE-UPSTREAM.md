# Quant engine original interfaces and hosting boundaries

Verified from official projects on 2026-09-07. Attached screenshots and shared recommendations are reference material; release numbers and licensing claims must be checked against upstream rather than treated as instructions.

| Project | Original interface available in this repository | What hosts it | Source and limits |
| --- | --- | --- | --- |
| Freqtrade | Vendored original FreqUI; the official container also serves FreqUI | Static frontend can be hosted on Vercel, with authenticated native API access to a persistent runtime | [FreqUI source](https://github.com/freqtrade/frequi), [Freqtrade API](https://www.freqtrade.io/en/stable/rest-api/) |
| NautilusTrader | Pinned genuine SDK examples and license, not a reconstructed GUI | Python/Rust SDK on a persistent runtime; original generated HTML reports may be viewed statically | [OSS source](https://github.com/nautechsystems/nautilus_trader/tree/v1.231.0); [Nautilus Pro](https://nautilustrader.io/pro/) is a separate commercial product, not the OSS web interface |
| Hummingbot | Original API and Streamlit Dashboard local installer | Python Streamlit + API + database + broker, with persistent server processes | [Original Dashboard](https://hummingbot.org/dashboard/) is deprecated; [Apache-2.0 source](https://github.com/hummingbot/dashboard). It cannot be converted to a static Vercel site by copying Python pages |
| QuantConnect LEAN | Pinned genuine Python/C# SDK examples and license | .NET engine and native reports; local development uses Docker/CLI or the official local platform | [Apache-2.0 engine source](https://github.com/QuantConnect/Lean). The hosted QuantConnect IDE is not the same artifact as the open-source engine |
| Jesse | Genuine compiled Nuxt UI from the MIT v3.1.1 core archive, with source provenance and small base-path/session adaptations | Static assets can be served on Vercel; native backend requires Python, PostgreSQL and Redis | [Jesse v3.1.1](https://github.com/jesse-ai/jesse/tree/v3.1.1). The old public Vue Dashboard repository is not the current Nuxt source project; this package vendors the actual current compiled assets |
| OctoBot | Original local Docker server/web interface | Python Flask/Jinja/SocketIO server with persistent configuration and tentacles | [Core GPL-3.0 source](https://github.com/Drakkar-Software/OctoBot/tree/2.1.1); web-interface source is under the monorepo's tentacles packages with its own LGPL notices. Copying static files alone does not reproduce the original application |

Jesse's original native login returns a SHA-256 digest of the local configured password; the same credential authenticates native HTTP and WebSocket requests. Embedded Vercel assets use a non-secret session marker for the site's BFF, never the native password/digest. Native WebSocket/LSP bootstrap is disabled in that embedded build because a session marker cannot authenticate directly to the original backend. Its full original interactive stream works from the user's local native Jesse server. The MIT core does not include a free commercial live license. The local installer deliberately omits `jesse install-live`; [official live-trading terms and prerequisites](https://docs.jesse.trade/docs/live-trading/) must be met independently.

Supabase hosted Edge Functions run a Deno-based JavaScript/TypeScript runtime with WebAssembly support. Hosted limits include 256 MB memory, 2 seconds of CPU time per request, and worker wall-clock limits of 150 seconds on the free plan or 400 seconds on paid plans; request idle timeout is 150 seconds. Background `waitUntil` work still shares the worker's lifetime. These bounds do not provide a persistent Python/Rust/.NET trading host. Supabase is suitable for the database, account isolation, device pairing and durable command queue; a connected persistent host executes native engines. See [official limits](https://supabase.com/docs/guides/functions/limits), [function runtime](https://supabase.com/docs/guides/functions), and [background tasks](https://supabase.com/docs/guides/functions/background-tasks).

The Windows local package provides that persistent host through Docker Desktop on the user's machine. See [the local installer contract and actual readiness boundaries](../quant-runtime/local-engines/README.md). UI availability, successful dependency installation, research validation, and live-trading authorization remain separate evidence. None of the vendored sources, generated manifests or mocked tests asserts that six engines have completed real-money production acceptance.
