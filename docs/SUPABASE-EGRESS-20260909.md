# Supabase Egress 排查与修复（2026-09-09）

## 证据与范围

用户截图显示本账期 Egress 约 2.34 GB，9 月 8 日明显增长。线上日志显示托管网格控制台反复同时请求十二个交易所状态、代理配置/检测和 AI 状态。

只读检查生产 `pg_stat_statements`：托管机器人按用户读取整行约 54,278 次；旧版后台按 ID 读取整行约 38,078 次，心跳更新返回整行约 37,907 次。统计是数据库累计值，不能据此精确分摊某一天的账单。间隔约 259 秒的复采样中，前端整行读取增加 60 次，旧后台读取/心跳增加 0 次；六个托管机器人均处于 READY，没有为此停止任何交易任务。

根因是请求放大叠加冗余字段：每个面板独立 1.5 秒轮询，托管 EventSource 还被转换为 1.2 秒轮询；每次请求重复鉴权并读取全部运行恢复快照。市场接口也读取所有交易所目录后才在应用内筛选。

## 改动

- 托管浏览器桥将状态、总览、对冲、代理和 AI 展示请求合并为一个 `/api/grid-ops-hosted/poll` 请求。运行时缓存 5 秒，空闲时缓存 30 秒；同一 iframe 的并发请求共享一个请求。
- 隐藏页面暂停读取；错误退避 5 秒；写操作后立即失效展示缓存，并阻止旧请求覆盖新缓存。凭据接口、交易写操作不进入缓存。
- GET 读取机器人元数据时不再加载运行恢复快照，也不唤醒现有后台工作流。首次创建仍执行初始化，交易命令仍显式唤醒引擎。
- 在 PostgreSQL 内投影单个交易所状态、展示总览或指定市场目录。每次读取仍执行原有用户/会员/双重验证权限检查；SQL 同时限制机器人 ID 与当前用户 UUID。
- 部署排除规则补充本地交易状态、凭据文件和诊断产物。

## 验证

生产数据库只读验证覆盖六个机器人：新投影与原快照展示内容完全一致，跨用户查询返回空对象。按紧凑 JSON 编码，原快照约 20–25 KB，单个交易所状态约 698 B（该查询载荷约减少 97%）；总览约 7–8.5 KB。该比例仅描述这些状态查询，不代表全组织账单必然同比下降。

回归测试覆盖并发合并、活跃/空闲刷新、隐藏页面、授权错误、网络失败退避、缓存隔离和写入期间的旧请求竞态。原有交易指令、加密配置和实盘确认逻辑保持执行路径。

部署后刷新已打开的托管控制台，使旧页面载入新版轮询脚本。账期已经累计的流量不会清零；观察后续小时/天的增量。Supabase 用量面板可能延迟约一小时更新。
