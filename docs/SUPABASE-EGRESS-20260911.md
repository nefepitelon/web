截图账期累计 3.36 GB。本次通过生产数据库查询统计、数据库内字节聚合和 Vercel 日志复查，发现自动交易筛选明细新增了高流量读取路径。

## 定位与证据

自动交易面板运行时每 15 秒刷新。`automationSnapshot` 在数据库中读取最近 30 条完整审计 `metadata`，随后才在应用服务器生成筛选摘要。缩小 HTTP 响应无法消除数据库到服务器的 Egress。

生产只读采样时间为 2026-09-11 02:02:44（北京时间）。同一账户最近 30 条记录，按数据库 JSON 字段投影比较：

| 查询 | 返回内容字节数 |
| --- | ---: |
| 原查询：状态、消息、时间、完整 metadata | 1,653,650 |
| 新查询：ID、状态、消息、时间 | 5,502 |

该查询载荷减少 99.67%。这是数据库内 JSON 文本大小，不包含连接协议开销，也不代表整个组织账单降幅。统计只返回聚合数字，未下载整批审计内容。最近 24 小时自动交易路径有 1,686 条日志；日志条目不等同于独立请求，不能据此计算精确账单。

## 修复

- 定时列表查询彻底不选取 metadata，只返回简要事件及明细入口。
- 操作者点击某一条筛选明细时，新增只读接口按事件 ID、当前用户 ID 和 AUTO_SCAN 状态查询单条记录。仍使用原有白名单摘要函数，完整原始审计保留。
- 页面合并同一记录的并发明细请求，并复用已读取结果；只保留当前最近 30 条记录的缓存。失败可再次点击重试。后台刷新不会自动请求明细。
- 无数据库迁移；不改变交易授权、策略、持仓、下单流程或正在运行的任务。
