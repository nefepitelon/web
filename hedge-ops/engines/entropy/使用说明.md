# Parallax Hedge（Arcus × Entropy）使用说明（从零开始）

这份说明写给**第一次接触这个程序的人**。从下载、准备两个交易所账户、每一个设置该填什么、去哪里找，
到网页面板上每个按钮和每一列是什么意思、出了问题怎么排查，都按顺序写清楚了。
照着从第 1 章做到第 7 章，就能先用演练模式跑起来，再切到小额实盘。

> ⚠ **风险提示**：永续合约交易可能损失全部本金。这个程序只负责「用尽量低的磨损在两个所开出方向相反的仓位来产生交易量」，
> 不保证盈利。两所之间的价差、手续费、资金费、极端行情下的强平都可能造成亏损。请先演练、再小额、再慢慢放大。
>
> ⚠ **合规提示**：Arcus 和 Entropy 都有地区限制（例如 Entropy 的条款列出了美国、加拿大、巴拿马、英国等受限地区，并禁止用代理 / VPN 绕过限制）。
> 请先确认你所在的地区可以使用，并遵守两个所的用户条款。程序的代理功能是为了网络稳定和给每个所单独的出口，不是用来规避地区限制的。

## 1. 这个程序在做什么

- 在 **Arcus** 和 **Entropy** 两个永续合约交易所，对同一个币种各开一个仓位：**一边做多、一边做空，数量相同**。
  价格涨跌时两边盈亏基本抵消。
- **Entropy 是什么**：Entropy 是部署在 Hyperliquid 上的一个 HIP-3 子交易所（内部名字叫 `io`），上面的币种名字都带 `io:` 前缀，
  例如 `io:SNDK`。你的钱和仓位都在你自己的 **Hyperliquid 账户**里，程序通过 Hyperliquid 的官方接口下单。
- 持有一段时间（你设定的「轮换周期」）后两边一起平掉，冷却一会儿再开新的一对。每开平一次，两个所都会产生交易量。
- 持有期间，两个所的资金费率不一样，程序开仓时会选**能收到资金费差**的那个方向。
- 程序会一直盯着两边离强平还有多远，太近了就**两边同时平掉**，绝不只平一边。

两个所的保证金模式**不一样**，这一点会影响你设的杠杆（第 9.3 节细讲）：

| | Arcus | Entropy |
| --- | --- | --- |
| 保证金模式 | **全仓**：整个 Arcus 账户的钱一起给所有仓位兜底 | **逐仓**（只支持逐仓）：每个仓位只拿自己的保证金兜底 |
| 离强平多远由什么决定 | 账户权益 ÷ 仓位总额 | 只由这个仓位的杠杆决定：约 `1/杠杆 − 维持保证金率` |
| 程序怎么处理 | 按最坏情况（账户里所有仓位一起亏）估算 | 自动把杠杆压到「守得住开仓门槛」以内 |

你需要做的：在两个所各准备一点保证金、Arcus 创建一把 API 密钥、Hyperliquid 创建一个 API 钱包、填进配置文件、在网页上建任务、点启用。

## 2. 准备工作清单

| 项目 | 说明 |
| --- | --- |
| 一台 Windows 10 / 11 电脑（64 位） | macOS / Linux 也能跑，见第 3.3 节 |
| 能正常访问两个交易所的网络 | 需要的话，程序支持每个所单独配代理（第 6.3 节） |
| 一个**普通的** EVM 钱包（MetaMask、OKX 钱包等） | 用来登录 Arcus 和 Hyperliquid、给 API 密钥签名授权。可以是同一个钱包。**登录 Entropy 网页时也请用这个钱包，不要用邮箱登录**，原因见第 5.1 节 |
| Arcus 上的保证金 | 充到 Arcus 账户里（抵押币种以 Arcus 官方为准，官方文档写的是 USDG） |
| Entropy（Hyperliquid）上的保证金 | USDC（从 Arbitrum One 充入 Hyperliquid），并确保这笔钱能被 Entropy 的 `io` 子交易所使用（第 5.2 节） |
| 两边金额尽量接近 | 仓位大小由**钱少的那一边**决定，两边差太多，钱多的那边就闲着 |

> 小额试跑：两边各 50～100 美元足够。第一次实盘建议把每个任务的「开仓金额」设成 20～30 USDC。
> 注意 Entropy（Hyperliquid）每笔订单**至少 10 美元**，开仓金额不要低于这个数。

## 3. 安装与第一次启动

### 3.1 下载

把整个项目文件夹放到一个**路径里没有中文、没有空格**的位置，例如 `D:\ParallaxHedgeEntropy\`。
（路径里有中文或空格大多数时候也能跑，但少数电脑上 Python 会出怪问题，没必要冒这个险。）

### 3.2 Windows：双击 `一键启动.bat`

第一次运行会自动做这几件事，窗口里能看到进度 `[1/4]`～`[4/4]`：

1. **找 Python 3.11 或 3.12。** 电脑上没有，就自动下载官方的 Python 3.11.9 安装包并**只为当前用户**安装
   （装到 `%LOCALAPPDATA%\Programs\Python\Python311\`，不需要管理员权限，不改系统 PATH）。
   python.org 下载失败会自动改用国内镜像。
2. **建虚拟环境**：在项目目录下建一个 `.venv` 文件夹，程序的所有依赖都装在这里面，不影响电脑上的其它软件。
3. **装依赖**：默认从 PyPI 装（包括 Hyperliquid 官方 Python SDK），失败会自动改用清华镜像。第一次需要几分钟。
4. **生成 `.env`**：从 `env.example` 复制一份，默认是演练模式（`DRY_RUN=true`），**不会下任何单**。
   然后启动面板，浏览器自动打开 `http://127.0.0.1:8005/`。

以后每次启动只需要几秒。**关掉那个黑色窗口 = 停止程序**。

> 如果杀毒软件（例如 360）拦截了 `.bat` 或 Python，请选择「允许」或把项目文件夹加入信任。
> 如果自动安装 Python 失败，手动去 <https://www.python.org/downloads/release/python-3119/>
> 下载「Windows installer (64-bit)」，安装时勾选 **Add python.exe to PATH**，再双击 `一键启动.bat`。

### 3.3 macOS / Linux

先自己装好 Python 3.11 或 3.12，然后在终端里：

```bash
cd 项目目录
./start.sh
```

### 3.4 第一次打开面板时你会看到什么

没填任何密钥也能打开面板：「资金费总览」页能看到两个所共有的币种和资金费率，这说明网络是通的。
账户余额、持仓这些要等第 4～6 章填好密钥后才会出现。

> 两个所「共有」的币种才会出现：程序把 Arcus 的 `SNDK` 和 Entropy 的 `io:SNDK` 这样按名字配对。
> Entropy 上的币种不多（主要是美股、未上市公司股权这类），所以共有币种可能只有几个，这是正常的。

## 4. 准备 Arcus 账户和 API 密钥

官方文档：<https://docs.arcus.xyz>（API 密钥的步骤见 <https://docs.arcus.xyz/guides/rest-trading>）

### 4.1 注册并入金

1. 打开 Arcus 网页端 <https://app.arcus.xyz>，用钱包连接（也支持邮箱 / 社交账号登录，会自动创建一个内置钱包）。
2. 按网页提示入金。Arcus 有地区限制和准入要求，以官方说明为准（帮助中心：<https://help.arcus.xyz>）。

### 4.2 找到你的钱包地址 → 填 `ARCUS_ADDRESS`

- 网页右上角显示的就是你登录用的钱包地址（显示成 `0xF4F9…538a` 这种缩写），点开账户菜单复制**完整地址**。
- 格式：`0x` 开头 + 40 位十六进制，共 42 个字符。
- 这是**公开地址**，不是私钥，泄露了也不能动你的钱。但它会暴露你的持仓和交易记录。

### 4.3 创建 API 密钥 → 填 `ARCUS_API_PRIVATE_KEY`

按 Arcus 官方文档的网页流程：

1. 打开 API Keys 页面：**<https://app.arcus.xyz/api-keys>**，连接你的交易钱包。
2. 输入一个名字（随便起，例如 `parallax-entropy`），点 **Generate**。密钥对是在你的浏览器里生成的。
3. **立刻复制「API Signing Key」**。这是私钥，**只显示这一次，关掉就再也找不回来**。
   先把它粘贴到 `.env` 的 `ARCUS_API_PRIVATE_KEY=` 后面，或者存到一个只有你自己能打开的地方。
4. 选择 **Subaccount #**：保持默认的 **0**（见下面 4.4）。
5. 选择 **Days Valid**（有效天数）：最长 **180 天**，建议直接选 180。
6. 点 **Authorize**，在钱包里确认签名。

> ⚠ **Arcus 的 API 密钥会过期**（官方规定 1～180 天，不选默认 14 天）。过期后程序下单会被拒绝。
> 建一个日历提醒，到期前重新生成一把，把新私钥换进 `.env`，重启程序。

程序认得的私钥格式：64 位十六进制（最常见）、128 位十六进制（私钥 + 公钥连在一起）、PKCS#8 PEM / DER。
前面带不带 `0x` 都行。

> 如果你同时在跑别的 Arcus 程序，**也可以**给这个程序单独建一把 Arcus 密钥（推荐），这样某个程序的密钥出问题不会影响另一个。

### 4.4 子账户编号 → 填 `ARCUS_ACCOUNT_INDEX`

- Arcus 一个钱包最多 10 个子账户，编号 0～9，**0 是主账户**。
- 网页端目前只能操作主账户 0（子账户和内部划转只能通过 API 操作），所以**绝大多数人填 0**。
- 这个编号必须和 4.3 第 4 步选的 Subaccount # 一致，而且你的钱要在这个子账户里。

### 4.5 `ARCUS_API_KEY`（公钥）—— 留空即可

程序会从私钥自动推导公钥。如果你填了，就必须和私钥是一对，不然程序会拒绝下单（防止填错）。

### 4.6 私钥也可以放在文件里

不想把私钥直接写在 `.env` 里，可以把私钥单独存成一个文本文件，然后：

```
ARCUS_API_PRIVATE_KEY=
ARCUS_API_PRIVATE_KEY_FILE=C:\keys\arcus.txt
```

写相对路径的话，是相对于 `.env` 所在的文件夹。

## 5. 准备 Entropy（Hyperliquid）账户和 API 钱包

相关链接：Entropy 网页端 <https://entropy.io> · Hyperliquid 网页端 <https://app.hyperliquid.xyz> ·
Hyperliquid API 文档 <https://hyperliquid.gitbook.io/hyperliquid-docs>

先弄清楚一件事：**Entropy 没有自己独立的账户体系**，你在 Entropy 上的钱和仓位都记在你的 **Hyperliquid 账户**（也就是你的钱包地址）下面。
程序需要两样东西：

- 这个 Hyperliquid 账户的**地址**（`HYPERLIQUID_ACCOUNT_ADDRESS`）；
- 一个授权给这个账户的 **API 钱包私钥**（`HYPERLIQUID_PRIVATE_KEY`）。API 钱包只能下单，不能提现。

### 5.1 登录 Entropy —— 用钱包登录，不要用邮箱

1. 打开 <https://entropy.io>，选择**用钱包登录**（MetaMask、OKX 钱包、WalletConnect 等）。
2. 第一次使用时网页会让你签两次名：一次是「开启交易」（网页自己生成一个交易密钥，存在**你的浏览器里**），
   一次是授权 builder fee。按网页提示完成即可。

> **为什么不要用邮箱登录**：邮箱登录会给你自动生成一个「内置钱包」，这个钱包不在你的 MetaMask 里，
> 你很难再用它去 Hyperliquid 网页上创建 API 钱包（第 5.3 节）。用你自己的普通钱包登录，
> Entropy 和 Hyperliquid 网页用的就是同一个地址，后面的步骤都顺。
>
> **为什么程序不能直接用 Entropy 网页的交易密钥**：那个密钥只存在浏览器里，导不出来（清掉浏览器数据它就没了）。
> 所以程序要用你在 Hyperliquid 网页上另外建的 API 钱包（第 5.3 节）。两者互不影响。

### 5.2 入金

1. Entropy 的保证金是 **USDC**，从 **Arbitrum One** 网络充入 Hyperliquid（在 Entropy 网页或 Hyperliquid 网页的 Deposit 里操作都可以，
   钱包要切到 Arbitrum One 网络，并留一点 ETH 付 Gas）。
2. Hyperliquid 第一次对外操作时会收一次性的账户激活费（以官方为准）。
3. **钱要能被 Entropy 用上**：Hyperliquid 里，主交易所、现货和各个 HIP-3 子交易所的余额可能是分开的，取决于你的账户类型：
   - **统一账户（Unified Account）**：一份 USDC 各处通用，什么都不用做。面板上 Entropy 卡片的「持仓」一栏会显示「统一账户」。
   - **普通账户**：需要把 USDC 划到 Entropy（`io` 子交易所）里才能用。在 Entropy 网页上按提示入金 / 划转即可。
   填好密钥后，面板 Entropy 卡片上的「可用」就是程序看到的能用来开新仓的钱。**如果你明明充了钱但这里是 0**，多半是钱还没进 `io` 子交易所，见第 11 章。

### 5.3 创建 API 钱包 → 填 `HYPERLIQUID_PRIVATE_KEY`

1. 打开 **<https://app.hyperliquid.xyz/API>**（或在 Hyperliquid 网页顶部菜单 **More → API**），用**第 5.1 节登录 Entropy 的同一个钱包**连接。
2. 在名字一栏填一个**新名字**，例如 `parallax-entropy`。
   - 不要和你已有的 API 钱包重名：Hyperliquid 用同一个名字授权新钱包时，会**顶掉**旧的那个。
3. 点 **Generate**。页面会生成一个新的 API 钱包，显示它的**地址**和**私钥（Private Key）**。
4. **立刻复制 Private Key**，粘贴到 `.env` 的 `HYPERLIQUID_PRIVATE_KEY=` 后面（`0x` 开头的 64 位十六进制）。
   这个私钥**只显示这一次**。
5. 点 **Authorize API Wallet**，在弹窗里选择 **Days Valid（有效天数）**，建议选最大值（**180 天**），
   点 **Authorize**，在钱包里签名确认。
   - 如果授权失败，先确认这个账户里已经有钱（Hyperliquid 可能要求先入金）。
6. 授权成功后，这个 API 钱包会出现在同一页面的列表里，能看到名字、地址和到期时间。

> ⚠ **API 钱包也会过期。** 到期后程序下单会被拒（报 `User or API Wallet ... does not exist`）。
> 「实盘预检」里会显示还剩几天到期。到期前按上面的步骤重新生成一个，换掉 `.env` 里的私钥，重启程序。
>
> ⚠ **一个 API 钱包只给一个程序用。** Hyperliquid 的下单序号（nonce）按 API 钱包记，
> 两个程序共用同一个 API 钱包，在同一毫秒下单时后到的那张会被拒。要同时跑别的程序，就给它另建一个。
>
> 另外，Hyperliquid 官方建议**不要重复使用**已经删除或过期的 API 钱包地址，需要时就生成新的。
> 账户里长时间没钱时，交易所也可能把 API 钱包清理掉，到时重新生成即可。

### 5.4 找到账户地址 → 填 `HYPERLIQUID_ACCOUNT_ADDRESS`

- 就是你在 5.1、5.3 用来登录的那个**钱包地址**（主钱包地址）。在 Hyperliquid 网页右上角点你的地址就能复制完整地址。
- 格式：`0x` 开头 + 40 位十六进制。大小写都行，程序会自动转小写。
- ⚠ **不要填成 API 钱包的地址。** API 钱包只负责签名，钱和仓位都在主钱包地址下；填错的话程序会读到一个空账户。
  （实盘预检会检查「API 钱包私钥对应的地址」是不是授权给了你填的这个主钱包，填反了会直接报出来。）

### 5.5 手续费

- Entropy 上程序只吃单（IOC），实测吃单费约 **0.86 bps**（0.0086%）。这个费率来自 Entropy 当前的费率设置，**以后可能调整**，
  请以官方为准，并留意面板上的「每万美元磨损」。
- 资金费结算不收手续费。
- 手续费是从 Hyperliquid 的成交记录里读出来的实际值，不是估算（还没对上账的几笔才按平均费率估算，面板会标出来）。

### 5.6 杠杆上限

每个币在 Entropy 上有自己的最大杠杆（例如有的币 10×，有的只有 3×）。Entropy 只支持逐仓，
程序会自动按「守得住开仓门槛」再往下压一点（第 9.3 节）。你在任务里填多少都行，程序取能用的最小值，任务列表里会显示实际用的倍数。

## 6. 填写 .env —— 每一行的含义

`.env` 在项目根目录，用记事本就能打开（如果看不到这个文件，是 Windows 默认隐藏了扩展名 / 以点开头的文件，
在资源管理器里「查看 → 显示 → 文件扩展名 / 隐藏的项目」打开即可）。

**规则**：一行一个设置，`键=值`，等号两边不要加空格，值不要加引号。以 `#` 开头的是注释。
**改完必须重启程序才生效**（关掉黑窗口，再双击 `一键启动.bat`）。

### 6.1 必填（不填就只能看、不能交易）

| 键 | 填什么 | 去哪里找 | 示例 |
| --- | --- | --- | --- |
| `ARCUS_ADDRESS` | Arcus 钱包公开地址 | 第 4.2 节 | `0x1234...abcd`（42 个字符） |
| `ARCUS_ACCOUNT_INDEX` | Arcus 子账户编号 | 第 4.4 节，一般是 0 | `0` |
| `ARCUS_API_PRIVATE_KEY` | Arcus API 私钥（API Signing Key） | 第 4.3 节 | 64 位十六进制 |
| `HYPERLIQUID_ACCOUNT_ADDRESS` | Hyperliquid **主钱包**地址（钱所在的地址） | 第 5.4 节 | `0xabcd...1234`（42 个字符） |
| `HYPERLIQUID_PRIVATE_KEY` | Hyperliquid **API 钱包**私钥 | 第 5.3 节 | `0x` + 64 位十六进制 |

### 6.2 选填：密钥和接口地址

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ARCUS_API_KEY` | 空 | Arcus API 公钥。留空，程序会自动推导 |
| `ARCUS_API_PRIVATE_KEY_FILE` | 空 | 私钥改为从文件读取（第 4.6 节）。和 `ARCUS_API_PRIVATE_KEY` 二选一 |
| `ARCUS_API_URL` | `https://api.arcus.xyz` | 不要改 |
| `HYPERLIQUID_API_URL` | `https://api.hyperliquid.xyz` | 不要改（这是 Hyperliquid 主网；程序固定交易 Entropy 的 `io` 子交易所） |

### 6.3 选填：代理（独立 IP）

| 键 | 说明 |
| --- | --- |
| `ARCUS_PROXY` | 访问 Arcus 用的代理 |
| `ENTROPY_PROXY` | 访问 Hyperliquid（Entropy）用的代理，包括下单 |
| `GLOBAL_PROXY` | 上面两个没填时的共用代理 |

- 都留空 = 直连。优先级：各所自己的代理 → 共用代理 → 直连。
- 支持的写法：
  - `http://1.2.3.4:8080`
  - `socks5://用户名:密码@1.2.3.4:1080`
  - `1.2.3.4:1080:用户名:密码`（会按 socks5 处理，这是很多代理商给的格式）
  - `1.2.3.4:8080`（会按 http 处理）
- 用户名或密码里有 `@`、`:` 这类特殊字符时，推荐用 `1.2.3.4:1080:用户名:密码` 这种写法，程序会自动转义。
- Entropy 下单走的是 Hyperliquid 官方 SDK，程序会让它**从建立连接的第一次请求起**就走代理；
  socks5 代理会自动改成「由代理端解析域名」（`socks5h`）。依赖 `requests[socks]` 一键启动会自动安装。
- 「资金费总览」页的 Arcus / Entropy 卡片上，「网络出口」一栏显示每个所实际走的是「独立代理 / 共用代理 / 直连」（IP 会打码显示）。
- 再强调一次：请遵守交易所的地区限制，不要用代理去规避它。

### 6.4 选填：运行和风控参数

| 键 | 默认 | 含义 | 什么时候改 |
| --- | --- | --- | --- |
| `DRY_RUN` | `true` | `true` = 演练，只记录「本来会下什么单」，不下单；`false` = 实盘 | 做完第 7 章的检查后改成 `false` |
| `HOST` | `127.0.0.1` | 面板只在本机能打开 | 不要改成 `0.0.0.0`，面板没有登录密码 |
| `PORT` | `8005` | 面板端口 | 和别的软件冲突时改 |
| `ENGINE_CYCLE_SECONDS` | `20` | 引擎多少秒检查一轮 | 一般不改 |
| `MIN_CORRIDOR_PCT` | `3` | **开仓门槛**：估算的「离强平还有百分之几」低于它就不开。**同时决定 Entropy 逐仓最多能用多少倍杠杆**（第 9.3 节） | 想更保守就调大（Entropy 杠杆会跟着变低） |
| `CLOSE_CORRIDOR_PCT` | `1.5` | **平仓线**：持仓中任一条腿离强平小于它，两边立刻一起平 | 一般不改 |
| `LIQUIDATION_WARN_DISTANCE_PCT` | `5` | 面板上「危险」标红的提示线 | 一般不改 |
| `REOPEN_COOLDOWN_SECONDS` | `60` | 平仓后隔多少秒才允许重开 | 一般不改 |
| `ORDER_SLIPPAGE_BPS` | `10` | 吃单时最多容忍的滑点（1 bps = 0.01%） | 盘口很薄的币种开不出来时可以略调大 |
| `ARCUS_MAKER` | `false` | 没在任务里单独选「Arcus 下单方式」的任务，默认用限价挂单（`true`）还是市价吃单（`false`）。每个任务都可以在面板上单独选，见第 8.2 节 | 一般在面板上按任务选就行 |
| `MAKER_WAIT_SECONDS` | `120` | 挂单模式下每次挂单最多等多少秒 | 一般不改 |
| `FUNDING_REFRESH_SECONDS` | `30` | 资金费率多久刷新一次 | 不改 |
| `FUNDING_STALE_MAX_SECONDS` | `180` | 费率数据超过这么久没更新就视为过期、不开仓 | 不改 |
| `FUNDING_TIMEOUT_SECONDS` | `30` | 拉取费率的超时时间 | 网络很慢时可以调大 |

## 7. 从演练到实盘：推荐流程

**第 1 步：演练模式建一个任务**（`DRY_RUN=true`）

1. 面板左侧点「轮换任务」。
2. 按第 8.2 节填好表单，点「保存任务」，再在任务列表里点「启用」。
3. 等一两分钟，看下面的「执行记录」：应该出现「已开仓」（演练模式下是模拟的），数量、杠杆、方向是否符合预期。

**第 2 步：实盘预检**

点「任务列表」右上的 **「实盘预检」**。它**不下任何单**，只检查：

| 检查项 | 通过的样子 | 不通过怎么办 |
| --- | --- | --- |
| Entropy 下单通道 | 「Hyperliquid SDK 已连通（走的代理 / 直连），io 子 dex 共 N 个市场」 | 程序真的建一次下单客户端（会经代理拉一次市场表，不下单）。失败多半是：私钥没填 / 格式不对、主钱包地址格式不对、代理不通、依赖没装全（见第 11 章） |
| Entropy API 钱包 | 「0x12…ab 已授权给主账户（名称 xxx，还有 N 天到期）」 | 「没有授权给 …」：API 钱包没授权成功，或者 `HYPERLIQUID_ACCOUNT_ADDRESS` 填成了别的地址；「已过期」：按第 5.3 节重新生成。如果提示「填的是主钱包私钥」，说明你填了主钱包私钥，能用但很危险，请换成 API 钱包私钥 |
| Arcus 签名密钥 | 显示公钥前后几位 | 私钥格式不对 / 公钥和私钥不是一对 |
| 本机时钟 | 相差几秒以内 | Windows 设置 → 时间和语言 →「立即同步」 |
| Entropy / Arcus 可用保证金 | 显示余额 | 地址填错 / 没入金 / 钱没进 Entropy 的子交易所（第 5.2 节）/ 代理不通 |
| 市场精度字段 | 共有币种都读到了 | 网络问题，稍后重试 |
| 每个任务 | 会开多少、两边实际杠杆、离强平多远、Arcus 单「真签一遍」。设了金额区间的按**区间上限**检查 | 按提示调整杠杆 / 开仓金额。提示「SDK 里找不到 io:XXX」说明 Hyperliquid SDK 没加载到这个币，重启程序再试 |

**第 3 步：小额实盘**

1. 把任务的「开仓金额 最小」改成 20～30，「最大」先留空。
2. `.env` 里 `DRY_RUN=false`，保存，重启程序。面板右上角会变成红色的「实盘 · 会下单」。
3. 等第一笔真实开仓后，分别登录两个所的网页（Entropy 网页或 Hyperliquid 网页都能看到 `io:` 仓位），核对：
   两边仓位数量一样、方向相反；面板「持仓与强平距离」里的数字和交易所显示的对得上（强平价的差别见第 9.4 节）。

**第 4 步：放大**

跑几轮没问题后，再逐步调大开仓金额、增加币种；想省手续费就把任务的「Arcus 下单方式」选成「限价」。

**账户与交易统计**（三张卡片：Entropy、Arcus、合计）

| 字段 | 含义 |
| --- | --- |
| 账户权益 | 账户总价值（含未实现盈亏）。Entropy 卡片是 Hyperliquid 账户里 `io` 子交易所能用的那部分（统一账户时是整份 USDC） |

| 元素 | 含义 |
| --- | --- |
| 指针 / 中间的大数字 | **当前任务预估日交易量**（两所合计）：每个启用任务 每天轮数 × 4 × 单边金额，再加起来。金额区间取中值；每轮时间 = 平均持有时长 + 冷却 + 一个引擎周期 + 开仓复核约 25 秒（限价任务再加挂单等待时间） |
| 满刻度 / 理论上限 | 两边都用全部权益、同时守住开仓门槛，按最短轮换 0.1 小时、吃单开平能达到的日交易量。Arcus 一边按全仓最坏情况算；**Entropy 一边按「权益 × 守住门槛的逐仓杠杆 × 95%」算**。取两边里小的那个，并说明是被谁卡住 |

## 9. 程序的决策规则（它什么时候开、什么时候平）

每一轮（默认 20 秒）对每个启用的任务按这个优先级判断，**安全动作永远优先**：

1. **只剩一条腿** → 立刻市价平掉（哪怕任务是停用的）。
2. **风险触发**（离强平太近、两腿数量对不上、强平价数据异常）→ 两边同时平。
3. **任务被停用** → 有仓就平掉收尾。
4. **持仓到期** → 两边同时平（正常轮换）。
5. **空仓、冷却结束、所有检查通过** → 开仓。

某一个币种这一轮处理出错，只影响它自己，其它币种的风控和孤腿抢救照常进行。

### 9.1 开仓前的检查（任何一条不过就不开，原因写在执行记录里）

- 两个所的资金费数据正常、没过期。
- **两条腿各自**估算的「离强平的距离」都 ≥ `MIN_CORRIDOR_PCT`（默认 3%），按近的那条算。
- 两边保证金都够（各按各的杠杆算）、数量不低于两所最小下单量和最小下单金额（Entropy 每笔至少 10 美元）。
- 两所中间价相差不超过 3%（防止名字一样但不是同一个东西）。
- 先把两边杠杆设好（Arcus 全仓、Entropy 逐仓），**设不上就不开**。
- Arcus 的单能正常签出来（密钥、精度、单笔上限），**签不出来就连 Entropy 都不碰**。

### 9.2 仓位大小怎么算

`数量 = min(Entropy 可用 × Entropy 实际杠杆, Arcus 可用 × Arcus 实际杠杆) × 95% ÷ 价格`，
再按「开仓金额」截断（设了区间就按本轮随机抽到的金额），并对齐到两个交易所的数量精度。留 5% 余量是为了不被交易所以「保证金不足」拒单。

### 9.3 Entropy 的杠杆为什么会比你填的低

Entropy 只支持逐仓。逐仓时一个仓位只拿自己的那份保证金兜底，价格往不利方向走大约
`1/杠杆 − 维持保证金率` 就会被强平，**和账户里有多少钱无关**。

程序因此给 Entropy 算一个「守得住开仓门槛的最高杠杆」：

```
最高杠杆 = 1 ÷ (开仓门槛 + 维持保证金率 + 0.05% 手续费滑点预留)，向下取整
维持保证金率 = 1 ÷ (2 × 该币最大杠杆)
```

例子（开仓门槛 3%）：

| 该币最大杠杆 | 维持保证金率 | 守门槛最高杠杆 | 任务填 20× 时实际用 |
| --- | --- | --- | --- |
| 20× | 2.5% | 18× | 18× |
| 10× | 5% | 12×（比上限高，不额外压） | 10× |
| 3× | 16.7% | 5×（比上限高） | 3× |

Entropy 实际杠杆 = min(任务杠杆, 该币上限, 守门槛最高杠杆)。Arcus 是全仓，不受这一条影响。
把 `MIN_CORRIDOR_PCT` 调大，Entropy 能用的杠杆就会变低，同样的钱开出的仓位也会变小。

### 9.4 强平价为什么和交易所网页上显示的不一样

- **Entropy**：程序直接用 Hyperliquid 返回的逐仓强平价，和网页上应该基本一致。
- **Arcus**：程序对 Arcus 用的是**全仓**模式，同一个 Arcus 账户里所有仓位共用保证金。
  - **Arcus 网页上的清算价**：假设只有这一个币在动，其它币价格不变。
  - **程序显示的强平价**：假设账户里**所有 Arcus 仓位同时往不利方向走**（最坏情况）。

  美股之间、加密货币之间通常同涨同跌，行情真来的时候往往是一起动。所以程序的数字更保守，
  面板上会比 Arcus 网页显示的**更近**。风控按程序的数字判断。

同一个 Arcus 账户里开的币越多、名义金额越大，Arcus 那条腿的强平距离都会变近。如果看到「受阻：…估算的强平走廊只有 x%」，
看原因里写的是哪一边：是 Arcus 就往 Arcus 多充一点或把开仓金额调小；是「Entropy 逐仓」就把任务杠杆调低。

### 9.5 Arcus 限价挂单（任务里「Arcus 下单方式」选「限价」）

Arcus 挂单手续费是 0，吃单要付手续费；Entropy 那条腿始终是吃单。选了限价的任务：

- **开仓**：Arcus 挂只做 maker 的限价单，排在盘口最前面。**一有成交就立刻在 Entropy 吃单对冲同样的数量**
  （订阅 Arcus 成交推送，单腿暴露通常 1 秒左右；推送断了自动改为每 0.5 秒查一次）。
- Entropy 对冲单的成交结果在回执里立刻就知道：没成交（盘口刚好被吃掉）就马上放宽滑点再发一次，不用等。
- Entropy 每笔订单至少 10 美元：Arcus 零零碎碎成交的一小点，会攒够 10 美元再对冲；最后剩下不够 10 美元的零头，在 Arcus 吃单减掉，保证两边数量一致。
- 被别人抢到前面就撤单重挂。最多等 `MAKER_WAIT_SECONDS`，一点没成交就撤单（零成本），下一轮再挂。
- **只成交了一部分**：先按实际成交数量持有，之后每一轮继续挂单**补仓**，补到目标数量为止。
  补仓前同样检查保证金和强平距离，离轮换平仓不到几分钟就不补了。
- **平仓**：正常轮换 / 停用收尾先挂单平，等不到的部分改吃单平。**风控触发的平仓一律立刻吃单**，不等。
- **Entropy 对冲连补几次都失败**（盘口太薄）：撤掉 Arcus 挂单，没对冲上的那部分 Arcus 仓位立刻吃单平掉，**不留单腿**。
- 美股类币种在休市时段盘口薄，挂单成交会慢很多，这是正常的。

### 9.6 成交账本怎么对账

- 每发出一条腿就记一笔（订单号、数量、价格）。Entropy 的回执里直接带成交量和成交均价；回执说「没成交」的单不记账。
- 下单约 2 分钟后，程序拿订单号去两个所的成交记录里核对，换成交易所的实际成交价、数量、手续费：
  Entropy 用 Hyperliquid 的成交记录（按订单号 oid），Arcus 用 `/v1/fills`（按 orderId）。
- 对不全的单子会等一段时间（最多约 30 分钟），仍然对不全就按仓位实测的数量定稿，并如实标成「估算」。
- Hyperliquid 的成交记录接口只返回最近一段（最多 2000 条）。程序一直开着就没问题；如果程序关了很久、期间又在同一账户大量手动交易，少数旧单可能对不上，只会标成估算，不影响交易。

## 10. 日常运维

- **停止程序**：关掉黑色窗口。仓位会留在交易所，下次启动时程序会接着管理（包括到期平仓）。
  如果要长时间停，建议先在面板上把任务都停用、等仓位平完再关。
- **重启**：关掉窗口，再双击 `一键启动.bat`。如果提示端口被占用，说明旧窗口还开着，先把它关掉
  （**旧的那个还在下单**）。
- **密钥续期（两个都会过期）**：
  - Arcus API 密钥最长 180 天，到期前按第 4.3 节重新生成，换掉 `ARCUS_API_PRIVATE_KEY`，重启。
  - Hyperliquid API 钱包最长 180 天，「实盘预检」里能看到剩几天。到期前按第 5.3 节生成新的，换掉 `HYPERLIQUID_PRIVATE_KEY`，重启。
- **数据在哪里**：任务、执行记录、成交账本都在项目目录的 `data/` 文件夹（SQLite 数据库）。
  删掉 `data/` = 清空所有任务和统计（不影响交易所里的仓位）。换电脑时把 `data/` 和 `.env` 一起带走即可。
- **升级程序**：用新版本的文件覆盖旧的，**保留你的 `.env` 和 `data/`**，重启即可。依赖会自动更新。
- **和别的程序共用账户**：同一个 Hyperliquid 账户 / Arcus 账户上还有别的程序或你自己在手动交易时，
  **不要在两边交易同一个币种**（这个程序会把别人开的单腿当成孤腿平掉）；Hyperliquid 每个程序各用各的 API 钱包。

## 11. 常见问题与排错

**双击 `一键启动.bat` 一闪就没了 / 被拦截**
杀毒软件拦截了，把项目文件夹加入信任后重试。也可以先打开「命令提示符」，`cd` 到项目目录后输入 `一键启动.bat` 回车，这样能看到报错。

**提示 `PORT 8005 IS ALREADY IN USE`**
已经有一个在运行了（可能在任务栏里藏着），先关掉它。或者在 `.env` 里改 `PORT`。

**提示 `Could not find or install Python 3.11`**
按第 3.2 节的方法手动安装 Python 3.11，勾选 Add python.exe to PATH。

**提示 `Dependency install failed`**
网络问题。检查网络 / 系统代理后重试；脚本已经会自动尝试清华镜像。

**实盘预检：Entropy 下单通道失败**
- 「缺少 HYPERLIQUID_PRIVATE_KEY」/「不是有效的私钥」：私钥没填、复制不完整、多了空格或引号。应该是 `0x` + 64 位十六进制。
- 「HYPERLIQUID_ACCOUNT_ADDRESS 必须是 0x 开头的 40 位…」：主钱包地址格式不对。
- 「未安装 Hyperliquid 实盘依赖」：删掉项目里的 `.venv` 文件夹，重新双击 `一键启动.bat` 让它重装。
- 「配了 socks5 代理，但没装 PySocks」：同上，重新运行一键启动会自动安装。
- 连接超时 / 连不上：代理不通或网络问题。先把代理留空试一次直连，确认是不是代理的问题。

**实盘预检：Entropy API 钱包「没有授权给…」**
- 第 5.3 节最后的 Authorize 那一步没完成（钱包里签名被取消 / 失败），回到 API 页面看列表里有没有这个钱包。
- `HYPERLIQUID_ACCOUNT_ADDRESS` 填的不是你授权时连接的那个钱包地址。
- 你用邮箱登录的 Entropy，钱在内置钱包里，而 API 钱包授权给了另一个地址。见第 5.1 节，改用普通钱包。

**实盘下单报 `User or API Wallet 0x… does not exist`**
API 钱包过期了、被同名的新 API 钱包顶掉了、或者被交易所清理了。按第 5.3 节重新生成一个新的（用一个新名字）。

**Entropy 可用保证金是 0，但我明明充了钱**
- 钱还在 Hyperliquid 的主交易所 / 现货里，没进 Entropy 的 `io` 子交易所。普通账户需要划转进去（第 5.2 节）。
- `HYPERLIQUID_ACCOUNT_ADDRESS` 填成了 API 钱包的地址（第 5.4 节）。
- 网络或代理不通，或者你所在的地区被交易所限制。

**Entropy 下单报 `Order must have minimum value of $10`**
开仓金额太小，或者币价低、数量太少。把任务的开仓金额调到 10 美元以上（建议 20 起）。

**Entropy 下单报 `Insufficient margin`**
Entropy 那边的钱不够这笔逐仓仓位的保证金。调小开仓金额，或者往 Entropy 多充一点。

**执行记录里写 `Order could not immediately match`**
Entropy 的吃单在限价内没吃到对手（盘口瞬间被拿走了）。程序会按「没成交」处理：开仓时就不去 Arcus 下单；挂单对冲时会放宽滑点重发。偶尔出现是正常的；频繁出现说明这个币 Entropy 盘口太薄，可以把 `ORDER_SLIPPAGE_BPS` 略调大，或换一个币。

**实盘预检：Arcus 签名密钥失败**
- 「格式无效」：`ARCUS_API_PRIVATE_KEY` 复制得不完整，或者多复制了空格 / 引号。
- 「公钥和私钥对不上」：把 `ARCUS_API_KEY` 清空（留空让程序自己推导）。

**本机时钟相差太多**
Windows：设置 → 时间和语言 → 日期和时间 →「立即同步」。Arcus 会拒收时间偏差 30 秒以上的请求。

**Arcus 下单一直失败，报 401 / unauthorized / signature 之类**
最常见的原因是 **Arcus API 密钥过期**，按第 4.3 节重新生成。其次检查时钟和 `ARCUS_ACCOUNT_INDEX` 是否和密钥的子账户一致。

**两个程序共用一个 Hyperliquid API 钱包，偶尔报 nonce 相关错误**
给每个程序单独建一个 API 钱包（第 5.3 节）。

**任务一直「受阻」**
看执行记录里写的原因：
- 「Entropy 逐仓 x× 估算的强平走廊只有 y%，低于开仓门槛」→ 把任务杠杆调低（或调低 `MIN_CORRIDOR_PCT`，不推荐）。
- 「按 Arcus 账户权益 …（全仓）估算的强平走廊只有 x%」→ 调小开仓金额，或给 Arcus 多充钱。
- 「可开数量为 0（保证金不足）」→ 某一边没钱了（开仓记录里会写是被哪一边卡住）。
- 「拿不到两边的资金费率」/「费率数据存疑」→ 网络问题或交易所数据异常，等它恢复。
- 「两所中价相差 … bps」→ 这个币两边可能不是同一个东西，换一个币。

**执行记录里「开仓失败」，原因是「Arcus 设置 … 全仓失败」或「Entropy 设置 io:… 逐仓失败 / 被拒」**
开仓前设杠杆没成功，程序没下任何单。看后面交易所给的原因：杠杆超过该币上限、该币上有你手动挂的单 / 别的仓位、网络问题等。下一轮会自动重试。

**限价任务一直「未成交」**
盘口不活跃（比如美股休市时段），挂单等不到对手。可以换一个活跃的币种，或者把这个任务的「Arcus 下单方式」改成「市价」。

**配了代理以后，面板正常但 Entropy 下不了单 / 对冲要补单好几次**
先点「实盘预检」看「Entropy 下单通道」是否连通；连通但对冲经常补单、偶尔报连接断开，多半是代理线路不稳，
换一条更稳的，或者给两个所各配一条（`ARCUS_PROXY`、`ENTROPY_PROXY`）。

**执行记录里某个币种「出错」**
某个币种这一轮处理出错时，只影响它自己，其它币种的风控和孤腿抢救照常进行；它会在下一轮自动重试。连续出错就看后面的原因。

**净损益 / 每万美元磨损显示「—」**
还没有完整平过一轮（开了还没平）。平掉第一轮后就会出来，之后每平一次更新一次。

**磨损比预想的高**
- 选「市价」的任务，Arcus 每次开平都付吃单费；改成「限价」能省掉这部分。
- Entropy 的手续费是交易所实收的，如果 Entropy 调整了费率，磨损会跟着变。
- 盘口薄的币种价差大，换盘口厚的币种（下拉框靠前的）。

**面板上的强平价和交易所网页不一样**
Arcus 那条腿正常，见第 9.4 节；Entropy 那条应该基本一致，差得多就截图「系统」页排查。

**我在交易所网页上手动平了仓 / 手动开了仓**
程序下一轮会发现：两边都没了 → 清掉记录进入冷却；只剩一条腿 → 立刻平掉那条；
一对对冲好的仓位但程序没有记录 → 「接管」并开始计时。**不要在程序管理的币种上手动交易**，容易被当成孤腿平掉。

## 12. 安全须知

- **只使用 API 密钥 / API 钱包。** 永远不要把钱包助记词或主钱包私钥填进任何程序。
  - Arcus 的 **API 私钥**能下单，但官方文档写明用 API 密钥发起的提现只能提回账户自己的钱包。
  - Hyperliquid 的 **API 钱包**只能代你下单，**不能提现**（提现必须主钱包每次单独签名）。
  即便如此，泄露了别人也能用它乱下单，同样要保管好。
- 预检如果提示「填的是主钱包私钥」，请马上换成 API 钱包私钥：主钱包私钥能把钱转走。
- `.env` 里有你的私钥：**不要发给别人、不要截图发群、不要上传到 GitHub**（项目的 `.gitignore` 已经排除了它）。
- 怀疑密钥泄露：
  - Arcus：马上在 API Keys 页面撤销（Revoke）那把密钥，再生成新的。
  - Hyperliquid：在 <https://app.hyperliquid.xyz/API> 删除那个 API 钱包，再生成新的（用新名字）。
- 面板没有登录密码，所以 `HOST` 保持 `127.0.0.1`（只有本机能打开），不要改成 `0.0.0.0` 暴露到网络上。
- 这是开源软件，按「原样」提供。实盘前请自己读懂第 9 章的规则，从小额开始。
